## 3. 子任务 A：计算“已存索引下的回报”，不要混同物理时间

### 3.1 本轮必须修正的表述

“实际执行时间未知”不等于“现有训练定义下的经验回报无法计算”。

对第 j 个已存 transition，定义：

```text
C_j = len(rewards_j)                         # 本数据为 50
R_j = sum(gamma**i * rewards_j[i] for i in range(C_j))
G_j_stored = R_j + (0 if done_j else gamma**C_j * G_(j+1)_stored)
```

从每条已存 episode 的末尾往前递推，使用 **float64、gamma=0.99**。这只是沿已记录行为轨迹计算的 `stored_index_discounted_return`，不调用 actor/critic，不等同于 target actor 的期望 Q，也不是实测 critic 输出。

只有末段最后一槽奖励 1、每条 C=50、episode 有 N 条记录时，闭式结果为：

```text
G_start_stored = 0.99**(50*N - 1)
```

数学验收示例：

| N | 结果 |
|---:|---:|
| 1 | `0.611117239532865` |
| 24 | `5.842494637669255e-06` |
| 30 | `2.8652116063799276e-07` |

已存每相邻 transition 的 bootstrap 系数为 `0.99**50 = 0.6050060671375364`。这个计算不要求 50 对应真实物理控制步；恰恰需要明确它目前只是训练使用的存储索引。

**禁止把 `50*N` 标为实际 simulator step 数。禁止据此声称网络的 Q 必须等于某条样本回报。**

### 3.2 实施

先读取上轮 `episode_audit.csv` 的列名和原有 reader 源码，选择最短可靠路径。可从可信 replay 流式读取 episode_id/step_id/rewards/done/success，立即丢弃大数组；不要反序列化未知来源文件。验证新读取的数据身份和基本数量，若与记录不同则报告，不强行使用历史结论。

### 5.4 为后续 replay 重建保留的边界

以后使用“每个已完成逻辑控制步折扣一次”的定义时，一个有效区间可以表示为：

```text
obs_start
policy-space actions actually consumed / their exact provenance
rewards at the chosen logical control ticks
valid_len K
obs_end before reset
termination / truncation evidence
```

其数学形式是：

```text
R = sum(gamma**i * reward_i for i in range(K))
bootstrap_discount = gamma**K * bootstrap_allowed
```

这仅在 K 的计数和 reward 时间单位一致时成立。若采用物理子步或决策调用为折扣单位，需要另外定义，不能直接套这条公式。不要现在选新 gamma 或替换正式 target。

如果采用固定大小 padded tensor，未来还须处理训练损失、critic 输入和有效动作掩码之间的一致性；**不是只改 reward 位置或 bootstrap 指数即可自动完成所有适配**。这一点写入设计注意事项，不在本轮扩张成 trainer 重构。

termination 与 truncation 要分开记录。是否 bootstrap 取决于环境任务定义；超时不一律等同真终止，也不一律视为可 bootstrap。缺失语义时让 `bootstrap_allowed=null`。[S3]

|---|---|
| H=50、计划/实际只执行 10 行，非终端 | 只记录 10 个有效策略行，下一观测对应假时钟 10，不是 50 |
| 计划执行 10 行，在第 7 个逻辑步检测到成功并终止 | K=7，奖励对应完成的第 7 步；不得补成 index 49；保留终止前观测 |
| H=50、确实完整执行 50 行 | 能正确记录完整窗口；不得为了偏向“短前缀”而硬裁成 10 |
| 每个逻辑控制步推进 3 个 physics tick | 10 个逻辑步与 30 个物理步分别记录，不能混成同一计数 |
| 关节裁剪/夹爪阈值后命令与 proposal 不同 | 策略侧与控制侧值分别保留，来源映射准确，不用副本伪造 equality |
| 未消费完队列就由下一 proposal 替换 | 丢弃后缀不计为 executed；来源 ID 不串接 |
| 假环境因外部截断结束且随即 reset | final observation 与 reset observation 分开；truncation 不被硬写为任务失败终止 |
| 控制接口抛异常或完成状态未知 | 不产生伪造的 completed/reward/next state；原异常不被记录器掩盖 |
| 记录开关关闭，对比无记录器基线 | 假环境接收命令、返回值、调用次数、RNG 使用一致；关闭时无日志文件 |

另外至少做一项负例：仅有 proposal、没有任何完成事件的数据不得被校验器标为“已验证执行”。负例被正确拒绝才算测试通过。

用标准库 unittest 即可。建议命令形式如下，使用本次实际路径：

```bash
# 在每个运行测试的 shell 中先 source 本次 cpu_env.sh。
# 这里 WORK_DIR 必须是第 2 节已创建的同一个目录。
PY="/root/workspace/envs/openpi/bin/python"
PYTHONPATH="$WORK_DIR${PYTHONPATH:+:$PYTHONPATH}" \
  "$PY" -B -m unittest discover -s "$WORK_DIR/tests" -p 'test_*.py' -v
```

保留完整测试日志和原始退出码。不同类测试的结果在 `reports/mock_test_results.json` 汇总；证据类型始终为 `MOCK_TEST`。

真实 runner 集成补丁只做语法和静态接口检查。不要把“独立 recorder 测试 PASS”写成“真实 collector 已验证 PASS”。
